# GitHub ↔ پروژهٔ محلی ↔ Arena Agent — نسخهٔ 1.3

این پنل سه بخش کار را به هم وصل می‌کند: دریافت پروژه از GitHub روی سیستم شما، انتشار پروژهٔ محلی و دریافت commitهای جدید Agent، و فرستادن مشخصات پروژه/درخواست به گفتگوی فعلی Arena. **اتصال حساب محلی gh با اتصال رسمی GitHub داخل Arena یکی نیست.** این برنامه ابزار رسمی Agent/MCP نیست، مخزن ابری Agent را بدون انتخاب شما عوض نمی‌کند و نمی‌تواند دسترسی مخزن خصوصی را به Arena اعطا کند.

## نصب و اتصال حساب

1. نسخهٔ `Arena-Desktop-Setup-1.3.1-x64.exe` را نصب کنید. امضای دیجیتال ندارد؛ از خروجی مورد اعتماد استفاده کنید.
2. **Git و GitHub CLI (`gh`) رسمی همراه نسخهٔ Windows 1.3.1 هستند**؛ نصب جداگانه یا ویرایش PATH سیستم لازم نیست. نسخهٔ بدون حساب و تأییدشده با SHA-256 بسته‌بندی می‌شود؛ هیچ تنظیم یا اعتبارنامهٔ سازنده داخل آن نیست. فرایندهای Git و PowerShell برنامه ابزارها را در PATH اختصاصی خود می‌بینند. برای اجرای سورس، Git/gh نصب‌شده همچنان قابل استفاده‌اند. [مجوزها و سورس ابزارها](THIRD-PARTY.md).
3. در نوار بالا **GitHub** یا `Ctrl+Shift+G` را باز کنید و **بررسی اتصال** را بزنید. برنامه فقط اکنون ابزارهای نصب‌شده و حساب gh را بررسی می‌کند؛ شروع خود برنامه هیچ ورود/API GitHub خودکاری انجام نمی‌دهد.
4. اگر حساب وصل نیست، **ورود در مرورگر** را بزنید. اجازهٔ بومی شروع ورود را بخوانید؛ کد یک‌بارمصرفِ محلی را فقط در `https://github.com/login/device` وارد و مجوزهای رسمی GitHub CLI را بررسی کنید. در صورت نیاز دکمهٔ بازکردن صفحهٔ ورود را بزنید. رمز، کد ورود یا توکن را در چت Arena نفرستید.
5. gh از روش نگهداری اعتبارنامهٔ خودش استفاده می‌کند؛ بسته به نصب/سیستم، credential store، فایل تنظیمات gh یا متغیر محیطی از پیش تنظیم‌شده. برنامه توکن را استخراج/در فایل خودش ذخیره/به مدل ارسال نمی‌کند و `gh auth token` اجرا نمی‌کند. رابط فقط نام حساب و کد موقت ورود را نشان می‌دهد؛ کد بعد از پایان/لغو پاک می‌شود. Git در هر عملیات از helper ثابتِ همان gh استفاده می‌کند؛ نیازی به بازنویسی تنظیمات global Git شما نیست.

پاک‌کردن داده‌های محلی Arena یا حذف این برنامه، حساب gh سیستم را logout یا مجوز OAuth آن را باطل نمی‌کند. برای قطع آن، از امکانات حساب GitHub/GitHub CLI خودتان استفاده کنید. ممکن است برنامه‌های دیگر هم از همان حساب gh استفاده کنند.

## سناریو ۱: ادامهٔ یک پروژهٔ آمادهٔ GitHub

1. **مخزن‌های حساب من** حداکثر ۱۰۰ مخزن را فهرست می‌کند. برای مخزن عمومی/مشترک/خصوصی دیگر، `owner/repository` یا URL مستقیم HTTPS را وارد کنید؛ برای مخزن عمومی ورود لازم نیست؛ برای مخزن خصوصی حساب gh باید مجوز لازم را داشته باشد. Enterprise و URL فایل/PR/ZIP پذیرفته نمی‌شوند.
2. شاخه را مشخص کنید؛ خالی باشد شاخهٔ پیش‌فرض با Git از مخزن خوانده می‌شود، نه اینکه `main` حدس زده شود.
3. **پوشهٔ والد دانلود** را از پنجرهٔ بومی انتخاب و **دانلود پروژه** را بزنید. مقصد و شاخه را یک‌بار تأیید کنید. مخزن در زیرپوشه‌ای تازه clone می‌شود؛ پوشهٔ موجود جایگزین نمی‌شود. برای پروژه‌ای که قبلاً دانلود شده، **پروژهٔ محلی / مخزن موجود** را بزنید و ریشهٔ دقیق آن را انتخاب کنید.
4. پروژه هم در این پنل و هم به‌عنوان پوشهٔ شروع **ترمینال AI** انتخاب می‌شود. سایت/مدل نمی‌تواند مسیر دلخواه را از طریق IPC تحمیل کند. انتخاب پوشه sandbox نیست.
5. برای کار ابری، داخل سایت حالت Agent و اتصال GitHub رسمی حسابتان را باز کنید و مخزن را در رابط خود Arena انتخاب کنید؛ برای مخزن خصوصی این مرحله ضروری است. یک کادر پیام یکتای خالی و سازگار لازم است.
6. کارت را بنویس و **ارسال پروژه و درخواست به Agent** را بزن. پس از اجازه، فقط URL مخزن، شاخه، commit مشاهده‌شده و درخواست تو در گفتگوی فعلی قرار می‌گیرد؛ فایل‌ها، مسیر مطلق، نام‌های سایر مخزن‌ها و اعتبارنامه‌ها ارسال نمی‌شوند. دکمه، «ثبت ابزار» یا «attach مخزن ابری» نیست. اگر کادر مبهم/مشغول باشد یا پیش‌نویس داشته باشد، آن را بازنویسی نمی‌کند.
7. از Agent بخواه نتیجه را commit و push کند. کدی که فقط در sandbox ابری ساخته شده یا در پیام نمایش داده می‌شود ولی push نشده، هنوز در GitHub نیست و قابل دریافت نیست.
8. اگر Arena برای کار شاخهٔ اختصاصی مثل `arena/...` تعیین کرد، **فهرست شاخه‌ها** یا نام دقیق شاخه را استفاده و **انتخاب و دریافت این شاخه** را بزن. برنامه شاخه را از متن مدل حدس نمی‌زند یا از `main` بدون اطلاع جابه‌جا نمی‌شود. شاخه باید روی GitHub موجود باشد؛ انتخاب فقط با پروژهٔ تمیز و بدون reset/force انجام می‌شود. شاخهٔ محلی واگرا رد می‌شود. پس از تغییر، مجوز دریافت قبلی باطل است.
9. **دریافت خودکار از GitHub** را روشن و یک‌بار مخزن/شاخه/پوشه را تأیید کن. هر ۳۰ ثانیه commitهای pushشدهٔ همان شاخه بررسی و فقط با fast-forward دریافت می‌شوند؛ هر commit اجازهٔ تازه نمی‌خواهد. سقف مجوز یک ساعت است و با توقف، تغییر پروژه/شاخه/URL گفتگو، بارگذاری دوباره/قطع صفحه یا خروج باطل می‌شود. شروع دوبارهٔ برنامه آن را بازیابی نمی‌کند. بستن فقط پنل، دریافت را متوقف نمی‌کند؛ وضعیت در نوار بالا می‌ماند.

## سناریو ۲: انتشار پروژهٔ محلی و ادامه با Agent

1. **پروژهٔ محلی / مخزن موجود** را بزن و ریشهٔ دقیق پروژه را انتخاب کن. انتخاب زیرپوشهٔ یک Git دیگر، مسیر جابه‌جا/نامعتبر یا remote غیر GitHub پذیرفته نمی‌شود. HEAD جداشده باید ابتدا با Git خودت به شاخهٔ واقعی متصل شود.
2. برای پروژهٔ بدون `origin`، نام مخزن جدید را بنویس؛ زیر حساب متصل و **همیشه خصوصی** ساخته می‌شود. برای مخزن دارای origin، همان مقصد استفاده می‌شود؛ اگر عمومی است، پیش‌نمایش و هشدار نهایی صریحاً عمومی‌بودنش را نشان می‌دهند. برنامه visibility یا origin موجود را خودکار عوض نمی‌کند.
3. **آماده‌سازی و پیش‌نمایش انتشار** را بزن. اگر Git ندارد، با اجازهٔ جداگانه فقط `.git` محلی و شاخهٔ `main` ساخته می‌شود. الگوهای متداول `.env`/کلیدها، `node_modules` و خروجی‌های ساخت در `.git/info/exclude` محلی افزوده می‌شوند؛ فایل پروژه یا `.gitignore` بازنویسی نمی‌شود. نمونه‌های `.env.example/.sample/.template` فقط به‌علت نام حذف نمی‌شوند، اما محتوایشان همچنان بررسی می‌شود.
4. فهرست فایل‌های جدید/تغییریافته/حذف‌شده، مقصد، شاخه و هشدار تاریخچه را بخوان. اگر index از قبل stage داشته باشد، انتشار خودکار رد می‌شود تا stage جزئی شما مخلوط نشود. فایل با نام حساس/خروجی تولیدشده که از قبل در Git ثبت شده باشد، پیوند/زیرمخزنِ تغییرکرده، مسیر غیرعادی، الگوی محتوای حساس یا اندازهٔ بیش از حد نیز رد می‌شود. الگوها ممکن است مثبت کاذب بدهند؛ **کامل یا تضمین تشخیص همهٔ اسرار نیستند**.
5. **بررسی نهایی و انتشار در GitHub** یک اجازهٔ بومی برای همین مقصد/شاخه می‌گیرد. فایل‌ها قبل از stage دوباره با پیش‌نمایش مقایسه می‌شوند؛ تغییرشان باعث توقف و نیاز به پیش‌نمایش تازه است. سپس فایل‌های انتخاب‌شده stage و محتوای blob آن‌ها با پیش‌نمایش (با پذیرش تبدیل CRLF معمول Git) مقایسه می‌شود. فیلتر/encoding غیرمعمول می‌تواند انتشار را برای بررسی دستی متوقف کند. در ادامه، در صورت نیاز commit **بدون امضا** با نام حساب و نشانی noreply GitHub همان حساب ساخته، و فقط `HEAD` به شاخهٔ انتخابی push می‌شود. هیچ force-push، tag اضافی، merge/بستن PR یا Release انجام نمی‌شود.
6. انتشار خودکار به Arena پیام نمی‌دهد؛ **ارسال پروژه و درخواست به Agent** مرحلهٔ مجزای صریح است. بعد از انتخاب همان مخزن در خود Arena، مانند سناریوی اول ادامه بده.

**هشدار تاریخچه:** push ممکن است تمام تاریخچهٔ موجودِ reachable را ارسال کند، نه فقط فایل‌های این پیش‌نمایش. بررسی فایل‌های فعلی، اسرار حذف‌شده در commitهای قدیمی را تشخیص نمی‌دهد. قبل از اولین انتشار تاریخچه را بررسی کنید؛ مخزن خصوصی هم جای اطلاعات ورود/کلید خصوصی نیست. برنامه تاریخچه را پاک یا بازنویسی نمی‌کند.

## حفظ پروژه و محدودیت‌ها

- دریافت فقط روی **پروژهٔ تمیز، همان origin/شاخهٔ تأییدشده و fast-forward** انجام می‌شود. تغییر محلی یا فایل ثبت‌نشده، واگرایی، تغییر HEAD حین دریافت و خطای شبکه باعث توقف می‌شوند؛ reset، stash، clean و merge تعارض‌دار خودکار وجود ندارند. فایل ignored محلی که با commit ورودی برخورد کند نیز با `--no-overwrite-ignore` حفظ می‌شود.
- checkout شاخه و commitهای ورودی می‌توانند فایل‌های **ثبت‌شده** را اضافه، تغییر یا حذف کنند؛ این رفتار مجوز دریافت است، نه ضمانت حفظ نسخهٔ قدیمی. نسخهٔ پشتیبان مستقل داشته باشید. هم‌زمان با عملیات برنامه، از IDE/ابزار دیگر روی Git همان پوشه کار نکنید؛ برنامه نمی‌تواند تمام مسابقه‌های فرایندهای خارجی را قفل کند.
- Git و جلسهٔ ترمینال AI محلی هم‌زمان اجرا نمی‌شوند. انتخاب پوشه/شروع ترمینال محلی دریافت خودکار ابری را خاموش می‌کند؛ برای دریافت دوباره، ترمینال را قطع و مجوز دریافت تازه بدهید. برای کار مستقیم مدل روی فایل‌های محلی، راهنمای [TERMINAL.md](TERMINAL.md) برقرار است.
- حفاظت‌های انتشار این پنل، sandboxِ فرمان‌های PowerShell نیستند. اگر اجرای خودکار ترمینال را اجازه دهید، فرمان‌ها دسترسی واقعی کاربر به فایل، شبکه و ابزارهای gh دارند. چند الگوی واضح چاپ اعتبارنامه یا انتشار از ترمینال برای بررسی دستی می‌ایستند، اما قواعد قابل دورزدن/ناقص‌اند. از مدل نخواهید gh token، فایل hosts.yml یا credential store را بخواند.
- کد دانلودشده، وابستگی یا build خودکار اجرا نمی‌شود. hooks Git و fsmonitor در عملیات این پنل غیرفعال‌اند؛ submodule و LFS خودکار دریافت نمی‌شوند. **انتشار Git LFS پشتیبانی نمی‌شود** تا pointer بدون object مربوطه منتشر نشود. Git، gh و تنظیمات کاربر باید قابل اعتماد باشند؛ سایر رفتارهای Git/فیلترهای نصب‌شده یا اجرای بیرون این پنل مرز امنیتی این برنامه نیستند.
- این ناشر سبک برای حداکثر **۲۰۰۰ فایل**، **۲۰ MiB هر فایل** و **۱۰۰ MiB تغییرات** است. مخزن‌ها/فایل‌های بزرگ، LFS، submodule پیچیده، conflict و گردش‌کار امضای commit را با Git/GitHub Desktop خودتان مدیریت کنید. فهرست مخزن و شاخه در هر درخواست حداکثر ۱۰۰ مورد است؛ آدرس/شاخهٔ دقیق دیگر را می‌توانید وارد کنید.
- «توقف عملیات» مجوز دریافت و ادامهٔ مراحل را باطل و تلاش می‌کند فرایند متعلق به اجرا را خاتمه دهد. تغییر فایل، stage، commit یا مخزن ساخته‌شده روی GitHub را rollback/حذف نمی‌کند. شکست push ممکن است commit محلی یا مخزن خصوصی خالی باقی بگذارد؛ قبل از تکرار وضعیت را بررسی کنید. فرایندهای جداشده یا ارسال انجام‌شده قابل پس‌گرفتن نیستند؛ هشدار توقف را با Task Manager بررسی کنید.
- پروژه، پیش‌نمایش، لیست مخزن‌ها و مجوز دریافت در حافظه‌اند و در فایل تاریخچهٔ برنامه ذخیره نمی‌شوند؛ خود پوشهٔ Git، commit، info/exclude، اعتبارنامهٔ gh و پیام‌های سایت طبق طبیعتشان باقی می‌مانند. حذف برنامه پروژه‌ها یا مخزن GitHub را حذف نمی‌کند.

## آزمون‌ها و صداقت سازگاری

کنترل‌کننده با **Git واقعی و مخزن bare موقتِ آفلاین** برای clone، انتشار، دریافت چند commit، انتخاب شاخهٔ Agent، حفظ تغییر محلی/ignored file، واگرایی، لغو، stage قبلی، اسرار و LFS آزموده می‌شود. در این fixture فقط لایهٔ حمل HTTPS به مخزن موقت نگاشت و پاسخ حساب/ساخت مخزن GitHub شبیه‌سازی می‌شود؛ هیچ حساب واقعی یا مخزن عمومی/خصوصی آزمایشی ساخته نمی‌شود. IPC و DOM با fixture و بستهٔ واقعی Windows در CI بررسی می‌شوند. این آزمون‌ها تأیید ورود OAuth انسانی، انتشار زندهٔ GitHub یا تمام نسخه‌های رابط/Agent واقعی Arena نیستند؛ اگر اتصال رسمی Arena دسترسی ندهد یا کادر پیام عوض شود، برنامه آن را دور نمی‌زند.

## عیب‌یابی نسخهٔ اصلاحی

از نوار بالا **عیب‌یابی** را باز کنید. گزارش فقط وضعیت فنی و تعداد کادرها/دکمه‌هاست و با انتخاب صریح **کپی گزارش فنی** قابل ارسال است؛ متن چت/فرمان، مسیر، مخزن، حساب و token در آن صادر نمی‌شود. حالت «همراه برنامه» در بخش ابزارها یعنی به نصب Git/gh روی سیستم متکی نیستید. برای GitHub خصوصی از «ورود در مرورگر» استفاده کنید؛ مخزن عمومی و فهرست شاخه‌ها به ورود اجباری وابسته نیستند.

عملیات شبکهٔ پنل ابتدا پراکسی صریح محیطی را رعایت می‌کند، در غیر این صورت نخستین مسیر قابل‌تشخیص پراکسی نشست Electron/Windows را استفاده می‌کند. این ترجمه، همهٔ رفتارهای PAC/پراکسی سازمانی/احرازهویت NTLM را تضمین نمی‌کند. خطای شبکه با خروج از حساب یکی نیست؛ TLS غیرفعال یا اعتبارنامه به چت منتقل نمی‌شود.

بسته در Windows با Git/gh **واقعاً بسته‌بندی‌شده** و پیکربندی موقت تست می‌شود؛ helper فقط توکن **جعلی آفلاین** می‌گیرد. انتقال HTTPS خواندنی به metadata مخزن عمومی GitHub نیز بدون helper/ورود آزموده می‌شود؛ این، تأیید ورود حساب شما یا انتشار خصوصی نیست. اگر ارسال در صفحه گیر کند، برنامه دیگر تنها از موفقیت کلیک نتیجهٔ موفق نمی‌گیرد و کلیک را برای جلوگیری از پیام تکراری تکرار نمی‌کند.
