# ترمینال محلی برای مدل‌ها و Agent — نسخهٔ آزمایشی 1.2

این قابلیت **عامل رسمی Arena، MCP رسمی یا API ابزارهای Arena نیست**. برنامه یک دستورالعمل عادی را به همان مدل/Agent انتخابی در گفتگو می‌فرستد، درخواست ساختاریافتهٔ فرمان را از code blockهای صفحه تشخیص می‌دهد و PowerShell ویندوز شما را اجرا می‌کند. از نسخهٔ 1.2، می‌توانید **اجرای خودکار** و، جداگانه، **ارسال خودکار خروجی** را برای همان جلسه اجازه دهید؛ دیگر لازم نیست هر مرحلهٔ عادی را تأیید کنید. حالت دستی قبلی نیز باقی است. کلید API جداگانه‌ای لازم ندارد، اما استفاده تابع شرایط خود Arena و مدل است.

## Arena و Agent: چه چیزی محلی می‌شود؟

- خود سایت Arena داخل برنامه باز می‌شود؛ مدل‌ها، حالت‌ها، فایل‌پیکر و قابلیت‌های موجود حساب از رابط خود سایت استفاده می‌شوند. این بسته اشتراک یا قابلیت سمت سرور را باز نمی‌کند و تأییدهای داخلی خود سایت را تغییر نمی‌دهد.
- **ابزارهای داخلی Agent، مخزن و ترمینال ابری آن خودکار به سیستم شما منتقل نمی‌شوند.** فقط فرمان‌هایی که مدل/Agent با پروتکل این پل تولید کند روی Windows شما اجرا می‌شوند. صرف انتخاب پوشه، ثبت ابزار رسمی در Agent نیست.
- پل با یک کادر پیام و دکمهٔ ارسال یکتا کار می‌کند. Agent نیز تنها در صورتی از پل محلی استفاده می‌کند که کادر پیام سازگار داشته باشد و درخواست ساختاریافته را در پاسخ قابل مشاهده بسازد. Battle، دو مدل/درخواست‌کنندهٔ هم‌زمان یا صفحه‌ای با چند کادر مبهم پشتیبانی نمی‌شود. تشخیص همهٔ حالت‌ها تضمین‌شده نیست.
- این نسخه تضمین «تمام قابلیت‌های Arena» نمی‌دهد: دوربین، میکروفون، ضبط صفحه، موقعیت مکانی، اعلان‌ها و USB/HID/Serial همچنان غیرفعال‌اند. قابلیت وابسته به آن‌ها باید در مرورگرِ دارای مجوز استفاده شود. نشست مرورگر با برنامه جداست.

## سازگاری و آزمون‌ها

کاربر کارکرد نسخهٔ 1.1 روی سیستم خود را گزارش کرده است. در این پروژه، حالت دستی و حلقهٔ خودکار چندمرحله‌ای با **صفحه‌های مصنوعی آزمون**، کادر `textarea` و `contenteditable` و پاسخ شبیه‌سازی‌شدهٔ مدل بررسی می‌شوند؛ PowerShell واقعی و بستهٔ Windows نیز در CI آزموده می‌شوند. از محیط توسعه به سایت زندهٔ Arena دسترسی نداریم؛ این آزمون‌ها تأیید مستقلی برای DOM فعلی سایت، ورود واقعی، همهٔ مدل‌ها یا حالت Agent واقعی نیستند.

اگر صفحه آفلاین شود یا کادر/دکمهٔ یکتا تشخیص داده نشود، پیش‌نویس وجود داشته باشد، پاسخ مدل قالب صحیح نداشته باشد یا چند درخواست متفاوت دیده شود، اجرا انجام نمی‌شود/اتصال متوقف می‌شود. برنامه CAPTCHA، محدودیت ورود یا سیاست‌های سایت را دور نمی‌زند. پل فقط داخل همین برنامه و روی دامنه‌های دقیق `arena.ai`, `www.arena.ai`, `lmarena.ai`, `www.lmarena.ai` فعال می‌شود؛ صفحهٔ ورود، زیردامنه‌های دیگر و مرورگر خارجی به ترمینال وصل نیستند.

## شروع بدون تأییدهای تکراری

1. `Arena-Desktop-Setup-1.3.1-x64.exe` را نصب کنید؛ نصب قبلی را می‌تواند به‌روز کند. برنامه امضای دیجیتال ندارد.
2. داخل برنامه وارد Arena شوید و گفتگو/Agent دلخواه را با **یک کادر ارسال خالی و سازگار** باز کنید. انتخاب حالت و مدل از خود سایت است.
3. **ترمینال AI** (`Ctrl+Shift+T`) را باز کنید و **انتخاب پوشه** را بزنید. سایت یا مدل نمی‌تواند این مسیر را با IPC تعیین کند.
4. کار موردنظر را در پنل بنویسید. برای ادامهٔ بدون دخالت در مراحل عادی، هر دو گزینه را روشن کنید:
   - **اجرای فرمان‌ها بدون تأیید تک‌تک**
   - **ارسال خودکار خروجی به Arena و مدل/Agent**
5. **ارسال درخواست و شروع** را بزنید. پنجرهٔ بومی، پوشه و وضعیت دقیق هر دو مجوز و خطرهای آن‌ها را نشان می‌دهد. یک‌بار آن را بپذیرید. پیش‌فرض پنجره «لغو» است. هیچ مجوزی پیش از پذیرش داده نمی‌شود.
6. مدل می‌تواند فرمان بدهد؛ برنامه درخواست کامل و ثابت را می‌خواند، فرمان فاقد الگوی خطر شناخته‌شده را اجرا می‌کند و، اگر مجوز جداگانهٔ ارسال را داده باشید، پیش‌نمایش خروجی عادی را به همان گفتگو برمی‌گرداند. مدل سپس می‌تواند مرحلهٔ بعد را پیش ببرد؛ کپی/چسباندن دستی لازم نیست.
7. **توقف و قطع اتصال** مجوزهای جلسه و درخواست‌های معوق را باطل می‌کند و تلاش می‌کند درخت فرایند فعال را خاتمه دهد. بستن فقط پنل، جلسه را قطع نمی‌کند. نوار بالا همچنان وضعیت را نشان می‌دهد؛ پنل برای موارد نیازمند بررسی دوباره باز می‌شود، نه برای هر مرحلهٔ خودکار.

### چهار ترکیب مجوز

| اجرای خودکار | ارسال خودکار | رفتار |
| --- | --- | --- |
| خاموش | خاموش | هر فرمان با تأیید بومی اجرا می‌شود؛ هر خروجی با بازبینی و کلیک شما ارسال می‌شود. |
| روشن | خاموش | فرمان‌های عادی خودکار اجرا می‌شوند؛ خروجی بدون کلیک شما به گفتگو برنمی‌گردد. |
| خاموش | روشن | اجرا هنوز تأیید جداگانه می‌خواهد؛ خروجی عادی فرمان تأییدشده می‌تواند خودکار ارسال شود. |
| روشن | روشن | چرخهٔ فرمان و خروجی عادی با همان مجوز اولیه ادامه پیدا می‌کند. |

این‌ها **مجوزهای مستقل، موقت و فقط در حافظه‌اند**؛ در تنظیمات ذخیره نمی‌شوند. هر دو در شروع برنامه خاموش‌اند. تغییر URL گفتگو، قطع اتصال، بارگذاری دوباره یا بسته‌شدن صفحه/برنامه، پایان مهلت یا خطای متوقف‌کننده، آن‌ها را باطل می‌کند. جلسه حداکثر **۳۰ دقیقه یا ۲۰ درخواست** است؛ انتظار بی‌پاسخ مدل نیز بعد از ۱۰ دقیقه تمام می‌شود. یک گفتگوی تازه ممکن است هنگام ارسال پیام شروع URL بگیرد؛ پس از آن URL گفتگو مقید می‌شود، حتی قبل از اولین فرمان. برای تغییر مجوزها، جلسه را قطع و دوباره با اجازهٔ تازه شروع کنید.

### مواردی که هنوز برای بررسی می‌ایستند

برنامه برای چند **الگوی قابل تشخیص** مکث می‌کند، از جمله حذف داده، `git reset --hard`، مسیرهای بعضی اطلاعات ورود، تغییر حفاظت سیستم، ارتقای دسترسی، اجرای پویا/کدگذاری‌شده و بعضی روش‌های آپلود شبکه. متن کامل فرمان و دلیل در پنل نمایش داده می‌شود؛ تأیید بومی همان فرمان لازم است. خروجی چنین فرمانی نیز خودکار ارسال نمی‌شود. ردکردن درخواست هم خودکار به مدل گزارش نمی‌شود؛ می‌توانید متن نتیجه را دستی ارسال کنید.

خروجی دارای الگوی احتمالی password/token/کلید خصوصی، خروجی ناقص یا اجرای متوقف/غیرعادی نیز برای بازبینی می‌ایستد؛ **حتی اگر پیش‌نمایش آن ماسک شده باشد**. خروجی کاملِ ضبط‌شده پیش از کوتاه‌سازی بررسی می‌شود. خروج موفق یا ناموفق معمول با `exit code` غیرصفر می‌تواند خودکار برگردد تا مدل خطا را اصلاح کند. در حالت بازبینی، متن قابل‌ارسال را ویرایش کنید و **ارسال همین خروجی به مدل** را بزنید؛ فقط همان متن ارسال می‌شود.

**این قواعد، parser کامل PowerShell، تضمین تشخیص خطر یا مرز امنیتی نیستند.** روش‌های بسیار دیگری برای فرمان مخرب، شبکه یا افشای داده وجود دارد؛ متن فاقد هشدار لزوماً امن نیست. خودکارسازی یعنی اختیار دادن به محتوای غیرقابل اعتماد سایت/مدل برای اجرای واقعی. از آن تنها برای کار و داده‌های مورداعتماد و ترجیحاً محیط ایزوله استفاده کنید.

## دسترسی واقعی و خطرها

- **پوشهٔ انتخاب‌شده sandbox، jail یا مرز دسترسی نیست.** PowerShell با دسترسی همان کاربر Windows اجرا می‌شود؛ فرمان می‌تواند از پوشه خارج شود، فایل‌ها را بخواند/تغییر دهد/حذف کند یا به شبکه متصل شود. مجوز ارسال خروجی فقط پیام خروجی این پل را کنترل می‌کند؛ جلوی ارسال داده توسط خود فرمان را نمی‌گیرد.
- تمام متن صفحه، پاسخ مدل، توضیح «ایمن است» و خروجی ترمینال غیرقابل اعتمادند. nonce جلسه هویت رمزنگاری‌شدهٔ مدل نیست؛ صفحه می‌تواند بلوک فرمان بسازد. **با اجرای خودکار، بررسی موردبه‌مورد را آگاهانه کنار می‌گذارید**؛ الگوهای هشدار جای آن را نمی‌گیرند. برای کنترل دقیق‌تر حالت دستی را نگه دارید.
- برنامه UAC/Administrator را دور نمی‌زند؛ آن را با Run as Administrator اجرا نکنید مگر آگاهانه بخواهید فرمان‌ها همان دسترسی بالاتر را داشته باشند. ایزولاسیون واقعی نیازمند ماشین مجازی/Windows Sandbox و فایل‌های غیرحساس است.
- ماسک‌کردن بعضی tokenها، `API_KEY`/password و کلید خصوصی فقط کمکی و ناقص است. خروجی خام، مسیرها، توکن‌های نامعمول یا محتوای فایل‌ها ممکن است حساس باشند و **با ارسال خودکار بدون تشخیص از سیستم خارج شوند**. دادهٔ ارسال‌شده تابع سیاست‌های Arena/مدل است. مجوز اجرا به‌تنهایی هرگز مجوز ارسال خودکار نیست.
- سقف هر فرمان **۱۲۰ ثانیه** و حدود **۱۲۸ KiB خروجی ترکیبی** است. عبور از آن توقف را درخواست می‌کند. ورودی فرمان حداکثر ۸۱۹۲ نویسه است؛ نویسه‌های کنترل/جهت‌دهی نامرئی رد می‌شوند.
- برای هر درخواست یک PowerShell تازه با `-NoProfile -NonInteractive` ساخته می‌شود؛ متغیرها و `cd` بین فرمان‌ها حفظ نمی‌شوند. دستور ثابتِ ثبت‌شده در همان پوشه شروع می‌شود؛ payload بعدی یا تغییر متن سایت آن فرمان را عوض نمی‌کند.
- توقف با `taskkill /PID <owned-pid> /T /F` روی فرایند متعلق به همان اجرا انجام می‌شود؛ PID از سایت/IPC نمی‌آید. فرایند جداشده، سرویس یا کار زمان‌بندی‌شده‌ای که فرمان بسازد ممکن است باقی بماند. توقف، rollback تغییر فایل‌ها نیست؛ اگر توقف تأیید نشد Task Manager را بررسی کنید.
- توقف، دادهٔ قبلاً قرارگرفته در کادر سایت یا پیام ارسال‌شده را پس نمی‌گیرد؛ ارسال در حال انجام ممکن است پیش‌تر کلیک شده باشد. پیش‌نویس آماده‌شده ممکن است در صفحه بماند؛ قبل از شروع دوباره بررسی/پاکش کنید. برنامه پیش‌نویس شما را خودکار پاک یا جایگزین نمی‌کند.
- فرمان‌ها، خروجی‌ها، پوشه و مجوزهای خودکار در فایل تاریخچهٔ برنامه ذخیره نمی‌شوند. Windows، ابزارهای اجراشده یا نرم‌افزار امنیتی ممکن است لاگ خود را داشته باشند؛ پیام‌های فرستاده‌شده نیز در گفتگو هستند. پس از بازکردن دوبارهٔ برنامه ترمینال خاموش است.

## پروتکل و مرزبندی فنی

هنگام شروع، UUID تازه و قواعد درخواست همراه کار شما به مدل داده می‌شود. درخواست باید JSON منفرد در code block با فقط `type: terminal_request`, `session`, `seq`, `command` و `reason` اختیاری باشد. nonce و شمارهٔ مرحله دقیق‌اند؛ گزینه‌هایی مثل `cwd`, `admin`, `shell`, `url`, `autoExecute`, `autoShare` یا تنظیم spawn از مدل پذیرفته نمی‌شود. فرمان باید در دو snapshot متوالی یکسان دیده شود. هر مرحله فقط یک‌بار قابل اجراست.

مجوزها فقط پس از انتخاب محلی کاربر و تأیید بومی شروع، در کنترل‌کنندهٔ main ثبت می‌شوند. اجرای/ارسال خودکار مجوز ثبت‌شده، هویت جلسه، URL، مهلت و شمارهٔ مرحله را دوباره بررسی می‌کند؛ هیچ پرچمِ دورزدن تأیید از IPC خوانده نمی‌شود. توقف و تغییر epoch، جواب دیررسِ پنجرهٔ تأیید، نتیجهٔ فرمان قدیمی و ادامهٔ ارسال معوق را باطل می‌کند.

این قرارداد متنی است، نه فراخوانی native tools از طرف Arena. اگر مدل رعایت نکند، برنامه فرمان را حدس نمی‌زند یا از متن آزاد اجرا نمی‌کند. نتیجه با `type: terminal_result` و JSON escape‌شده به‌عنوان دادهٔ غیرقابل اعتماد ارسال می‌شود؛ Markdown خروجی نمی‌تواند خودش code block درخواست دیگری بسازد.

سایت همچنان `nodeIntegration: false`, `sandbox: true`, `contextIsolation: true` و **بدون preload** است. adapter فقط DOM را در world مجزا می‌خواند/متن ساده درج می‌کند؛ سرور localhost، پورت شبکه، endpoint اجرای فرمان یا `exec` عمومی در صفحه ساخته نمی‌شود. IPC ترمینال فقط از فریم اصلی فایل دقیق پوستهٔ محلی پذیرفته می‌شود. این مرزهای Electron برقرارند؛ آن‌ها فرمانی را که کاربر اجرای خودکارش را اجازه داده sandbox نمی‌کنند.


## پروژهٔ GitHub (نسخهٔ 1.3)

با انتخاب/دانلود پروژه در پنل **GitHub**، همان پوشهٔ بومی به این پل محلی متصل می‌شود و URL/شاخهٔ دقیق به دستور آغاز جلسه افزوده می‌شود. نشست فعال ترمینال و عملیات Git پنل هم‌زمان کار نمی‌کنند؛ انتخاب/شروع ترمینال، مجوز دریافت خودکار GitHub را باطل می‌کند. برای دریافت نتیجهٔ pushشدهٔ Agent ابری، جلسهٔ محلی را قطع و دریافت را دوباره فعال کنید. [راهنمای GitHub](GITHUB.md).

پل PowerShell همچنان sandbox نیست: gh نصب‌شده ممکن است به حساب واقعی GitHub شما دسترسی داشته باشد. چاپ توکن/credential file و چند الگوی واضح انتشار (`git push` و برخی عملیات نوشتن gh) برای بررسی دستی متوقف می‌شوند؛ این‌ها تشخیص ناقص‌اند، نه کنترل کامل شبکه یا تضمین جلوگیری از افشای اعتبارنامه. برای انتشار کنترل‌شده با پیش‌نمایش از پنل GitHub استفاده کنید؛ حفاظت‌های آن پنل بر فرمان دلخواه PowerShell اعمال نمی‌شوند. مدل/خروجی مخزن را قابل اعتماد فرض نکنید.

## بهبودهای عملکرد در 1.3.1

کادرهای پیام `textarea` و ویرایشگر غنیِ بدون role، نوار گفتگوی Agent بیرون از `main` و دکمهٔ ارسال تو‌در‌تو بررسی می‌شوند؛ کادر کد/جستجو/دیالوگ انتخاب نمی‌شود. متن چندخطی با مسیر ویرایش بومی Chromium درج می‌شود. برنامه پس از کلیک ارسال، مصرف پیش‌نویس یا حالت تولید پاسخ را بررسی می‌کند؛ این تنها تأیید UI است، نه رسید سرور. کلیک بی‌اثر دوباره تکرار نمی‌شود و پیش‌نویس باقی می‌ماند.

Git و gh همراه برنامه در PATH اختصاصی فرایندهای PowerShell قابل استفاده‌اند؛ PATH عمومی Windows تغییر نمی‌کند. runtimeهایی مثل Node.js یا Python و وابستگی‌های هر پروژه باید روی سیستم موجود باشند. `npm.cmd`/`npx.cmd` از مشکل shim پاورشل بدون پایین‌آوردن ExecutionPolicy جلوگیری می‌کنند؛ نصب نرم‌افزار یا تغییر حفاظت سیستم را به مدل تفویض نکنید مگر خودتان مشخصاً خواسته باشید.

اگر بعد از ۴۵ ثانیه درخواست ساختاریافته نرسد، پیام راهنما می‌آید؛ فرمانی حدس زده نمی‌شود. برای تشخیص مرحلهٔ مشکل، **عیب‌یابی ← کپی گزارش فنی** را بزنید. گزارش وضعیت خواندنی است، فرمان یا چت اجرا/ارسال نمی‌کند و اطلاعات چت/فرمان، نام مخزن/حساب، مسیر و توکن را صادر نمی‌کند. تست کادر غنی در Chromium واقعی Windows هم روی **صفحهٔ مصنوعی** است؛ ورود واقعی/همهٔ مدل‌های Arena یا تغییر ابزار ابری به محلی را ثابت نمی‌کند.
